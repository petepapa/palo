# Cline Rules — Accessible Astro Starter

## Project Overview
A ready-to-use, SEO and accessibility-focused Astro starter template with blog and portfolio functionality. Built as the flagship starter theme of the Accessible Astro ecosystem.

- **Framework**: Astro 5.x (SSG/static output)
- **Styling**: Tailwind CSS v4 (Vite plugin), SCSS utilities
- **Components**: `accessible-astro-components` library
- **Content**: MDX Content Collections (projects)
- **TypeScript**: Strict mode enabled

## Configuration System

### `src/config.yaml` is the single source of truth
All site customization lives in `src/config.yaml`. The file is imported via the `@config` alias:
```typescript
import themeConfig from '@config'
```

### Config structure
```yaml
site:
  name: string           # Site name (used in <title>, logo alt, etc.)

metadata:
  title: string          # Default page title
  description: string    # SEO description
  author: string         # Site author
  image: string          # Social share image path

branding:
  logo: string           # Logo SVG path
  colors:
    primary: string      # OKLCH color value
    secondary: string    # OKLCH color value
    neutral: string      # OKLCH color value
    outline: string      # OKLCH color value
  fontFamily: string     # CSS font-family value (e.g. "'Atkinson Hyperlegible', sans-serif")

layout:
  containerWidth: string # Max-width for container (e.g. '75rem')

typography:
  # ... typography settings

navigation:
  items: array           # Nav items with optional children (dropdowns)
  showDarkModeToggle: boolean

socials: array           # Social media link objects
```

### How to consume config in components
```astro
---
// Always import from @config alias
import themeConfig from '@config'
---
```

### What NOT to do
- ❌ Do NOT use `JSON.parse(__SITE_CONFIG__)` — this pattern has been removed
- ❌ Do NOT use `defineThemeConfig()` — this utility has been deleted
- ❌ Do NOT create separate navigation data files (e.g. `src/navigation.ts`) — data lives in `config.yaml`
- ❌ Do NOT reference `theme.config.ts` — this file no longer exists

### Build script modification protocol
- ⛔ **Forbidden**: modifying `astro.config.mjs` without prior confirmation.
- ✅ **Required**: any change involving build logic or build configuration must first be presented as a detailed plan with rationale, scope, and impact analysis. Wait for explicit approval before implementing.

### Tailwind v4 color mapping
Colors defined in `config.yaml` must be mapped to Tailwind semantic core classes via CSS `@theme` block:
```css
/* src/styles/tailwind.css */
@import "tailwindcss";

@theme {
  --color-primary: oklch(0.5 0.2 240);     /* references config.yaml → branding.colors.primary */
  --color-secondary: oklch(0.6 0.15 20);   /* references config.yaml → branding.colors.secondary */
  --color-neutral: oklch(0.95 0 0);        /* references config.yaml → branding.colors.neutral */
  --color-outline: oklch(0.3 0.06 260);    /* references config.yaml → branding.colors.outline */
}
```
Components **must only use semantic class names** (`text-primary`, `bg-secondary`, `border-outline`, etc.). Never reference raw color values or utility classes like `text-blue-500` in component templates or styles.

### Type safety
Config types are defined in `src/types/config.ts`. When adding new config fields:
1. Add the field to `src/config.yaml`
2. Update the corresponding type in `src/types/config.ts`
3. Import `themeConfig` in the component that needs the new field

## Key Conventions

### Fluid typography & spacing
- ❌ **Forbidden**: fixed units (`px`, `rem` without `clamp()`) for font sizes and spacing.
- ✅ **Required**: all font sizes and spacing values must reference `config.yaml` typography scale coefficients and use `clamp()` for fluid auto-scaling:
  ```astro
  <!-- ✅ Correct -->
  <h1 class="text-[clamp(2rem,5cqi,4rem)]">Title</h1>

  <!-- ❌ Wrong -->
  <h1 class="text-4xl">Title</h1>
  ```
- Spacing tokens (margin, padding, gap) follow the same rule: use `clamp()` with viewport-relative units for consistent scaling across breakpoints.

### Path aliases
- `@components` → `./src/components`
- `@layouts` → `./src/layouts`
- `@assets` → `./src/assets`
- `@content` → `./src/content`
- `@pages` → `./src/pages`
- `@public` → `./public`
- `@post-images` → `./public/posts`
- `@project-images` → `./public/projects`
- `@config` → `./src/config.yaml`

### Accessibility (WCAG 2.2 AA)
- Semantic HTML is required
- All interactive elements must be keyboard accessible
- Never remove focus outlines without accessible alternatives
- Use `prefers-reduced-motion` for all animations
- Proper heading hierarchy (h1-h6)
- Proper form labels and error messages
- Only use ARIA when native HTML is insufficient

### Commit format
Follow conventional commits: `type(scope): subject`
- Types: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`, `a11y`
- Example: `feat(config): add config.yaml as single source of truth`

### Build verification
Always run `npm run build` before completing work. The build must pass with 0 errors.
