# 全站图片加载体验优化 - 工作总结报告

## 一、项目背景与目标

### 1.1 问题起源
在低速网络环境下，全站大图组件的加载体验存在两大核心痛点：
- **透明 PNG 纯色块暴露**：透明 PNG 图片加载时，主色调占位块会透过透明区域暴露，形成"纯色闪烁"和"方块死色"的视觉瑕疵
- **体验不一致**：不同组件的占位策略、淡入动画、背景色消隐逻辑不统一，缺乏系统化的分层策略

### 1.2 优化目标
基于**"图片格式智能感知"**，建立一套**立体分流管线**，根据**图片格式（PNG vs 非 PNG）× 组件场景**实现差异化占位策略，达成：
- ✅ 零多余配置：系统自动识别 PNG，无需手动标记
- ✅ 场景精细化：复合图层不闪烁、正文流加载后通透、卡片流边界稳固
- ✅ 全链路闭环：从工具层到组件层的完整逻辑闭环

### 2.2 核心技术实现

#### 工具层：`isPngImage` 智能判断函数
**文件**：[contentImages.ts](file:///Users/petelee/工作/palo/src/utils/contentImages.ts#L48-L71)

支持三种输入形态的 PNG 格式判断：
1. **ImageMetadata 对象**：通过 `format` 属性精准判断（ESM 导入的本地资产）
2. **普通对象带 format 属性**：兼容性兜底
3. **字符串路径**：移除 URL 参数/hash 后判断扩展名（MDX Frontmatter、public 路径）

```typescript
export function isPngImage(src: unknown): boolean {
  if (!src) return false
  if (isImageMetadata(src)) return src.format.toLowerCase() === 'png'
  if (typeof src === 'object' && src !== null && 'format' in src) {
    const fmt = (src as { format: unknown }).format
    if (typeof fmt === 'string') return fmt.toLowerCase() === 'png'
  }
  if (typeof src === 'string') {
    const cleanSrc = src.split('?')[0].split('#')[0]
    return cleanSrc.toLowerCase().endsWith('.png')
  }
  return false
}
```
